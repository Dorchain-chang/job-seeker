# 从「检索问答」到 Agentic RAG：融合方案与创新点

> 状态：**方案稿（待批）**。本文回答两件事：①对标同类项目，本项目还能往哪走；②怎么把 RAG 与 Agent 的知识**自然地长进现有代码**，而不是贴两个时髦标签。
> 前置文档：`docs/AI-PLAN.md`（M0–M6 功能规划，已全部落地）、`docs/AI-FEATURES.md`（用户使用说明）。

## 0. 一句话结论

现状是**单路 BM25 检索 + 固定管线生成**（retrieve → 拼 prompt → 生成）。
目标是**有界 Agentic RAG 闭环**：路由 → 混合检索（稀疏 + 图谱双路）→ 证据自评（CRAG）→ 自愈重检 → 生成 → 引用校验（Self-RAG），全程可观测、可评测。

所有新增环节继续守原红线：**零后端 · 单文件 HTML · 数据不出本机 · 离线可用 · Mock 确定性 · 构建幂等**。

## 1. 现状盘点：差在哪

| 能力 | 现状（v47） | 2026 主流做法 | 缺口 |
|---|---|---|---|
| 检索 | 单路 BM25（标题字段加权 `RAG_TITLE_W=2`、`K1=1.5`/`B=0.75`、Top6），中文 2-gram 分词 | 稀疏 + 稠密**双路并行** → RRF 融合 → Cross-Encoder 精排 | 无双路、无融合、无精排 |
| 查询理解 | 原样分词 | 改写 / 扩展 / 实体识别 / 子问题分解 / HyDE | 全缺 |
| 反思 | 无 | CRAG 证据评分 + 三级兜底；Self-RAG 四标记 | 全缺 |
| 编排 | 固定「先检索再生成」；7 个 AI 能力是**并列按钮** | Agent 自主选工具 + 有界循环（迭代上限 / 超时 / 新块下限） | 无自主工具选择、无循环控制 |
| 图谱 | 无 | GraphRAG：实体链接 + 1~2 跳扩展，与检索路并集 | 全缺（作者有 KG-RAG 实战，最该补） |
| 记忆 | 会话最近 60 条（线性存储） | Storage → Reflection → Experience 三阶段 | 无反思、无经验抽象、无治理 |
| 评测 | 无（只能「看着像对的」） | HitRate/Recall/MRR/nDCG + Faithfulness/AnswerRelevancy + LLM-as-Judge | 全缺 —— **最影响说服力的一块** |
| 可观测 | `wb_ai_trace` 存最近 12 条，仅调参台内部用 | 每次问答的路由决策 / 轮次 / 命中 / 评分 / token / 延迟 | 未展示、未与问答关联 |

三层 AI 通道（BYOK / 零配置免费 / Mock）与 Agent 调参台（`AGENT_FNS` 7 项 + `wb_agent_tune` + 人设）已经是好底子，
**缺的不是「接个大模型」，而是「检索质量工程 + 编排控制 + 可度量」**。

## 2. 同类项目调研（8 个方向）

| 项目 | 形态 | AI 用法 | 对本站的启示 |
|---|---|---|---|
| Gsync/jobsync | Next.js + Docker + SQLite + Prisma | Ollama/DeepSeek 简历评审、JD 匹配打分、求职信、**内置 MCP server**、自动化发现、CRM/题库 | 功能最全，但**要起容器、要服务端**；我们的差异化在「一个 HTML 文件 + 数据不出本机」 |
| JobVault-Libre | Python，local-only | 几乎无 AI | 隐私优先的定位可借鉴，但 AI 深度不足 |
| jimpeel-tech/job-application-workbench | Windows 桌面 + 本地 LLM(Ollama) | 岗位捕获、适配度分析、生成简历/求职信 | 「本地 LLM」路线可行；但它锁 Windows 桌面 |
| matchbox | FastAPI + React + SQLite | **「AI 只能从你核实过的事实里选」** | 与我们的「引用式作答 / 只依据资料」同源，可把**事实边界**做成更强约束 |
| Career-Ops / ApplyTrail | CLI / React+Express | 关键词匹配、跟进提醒 | AI 很浅，说明「有 AI」本身不是壁垒，**检索质量**才是 |
| apply-potato / JobPilot-AI / handshake-notion-tracker | 爬虫 + Gmail/Sheets/Notion | 自动抓取、自动投递 | 依赖第三方账号与云端权限，隐私面大 |
| do-me/SemanticFinder | 纯前端 transformers.js（WebGPU/WASM） | 浏览器内 embedding + 余弦相似度语义检索 | **证明本机向量检索可行**，是我们「第二路检索」的现成技术路径 |
| Microsoft GraphRAG / LightRAG / Graphify / Semantica | 图增强 RAG | 实体-关系抽取、社区摘要、图遍历、MCP 接口 | 2026 三大关键词：**约束（本体）、结构（图）、问责（溯源+时间）** |

**结论：空位很明确。** 同类项目要么重后端（JobSync 类），要么 AI 很浅（Career-Ops 类），要么纯检索无 Agent（SemanticFinder 类）。
**几乎没有项目同时做到「本机 RAG 质量工程 + Agent 编排 + 可复现评测」**——这正是本项目该占的位置。

## 3. 六个创新点（按「与现有代码融合的自然度」排序）

### I1 · Agentic RAG 有界闭环（自适应路由 + CRAG 自愈 + Self-RAG 校验）
把 `ragAsk()` 从「一次检索就生成」改造成显式状态机：

1. **路由（Adaptive）**：规则优先（正则 / 长度 / 是否含实体 / 是否疑问句），**仅模糊时**才用 LLM 分类（省 token）。
   三档去向：`不检索`（如「你好」）· `单轮检索`（大多数）· `多轮`（多跳、对比类问题）。
2. **检索**：见 I3（混合检索）。
3. **证据自评（CRAG）**：不引入额外模型，用**确定性信号**打分——查询词覆盖率、命中文档数、BM25 分数边际、实体命中率。
   三档：`Correct`（直接生成）· `Ambiguous`（补检索 / 放宽 Top-K）· `Incorrect`（丢给兜底：改写查询重检 → 仍不行则**明确拒答**）。
4. **自愈**：重写查询（补同义词、拆分多跳、加实体词）后重检，**最多 3 轮**。
5. **生成 + 校验（Self-RAG 简化版）**：生成后逐句校验「是否被命中片段支撑」，把无支撑句标黄 / 剥离，并核对**引用序号是否真实存在**。
6. **硬边界**（工程可信度就体现在这里）：`max_iterations=3`、`min_new_chunks=1`（无新块立即中断）、单轮超时 12s、上下文 token 预算、
   超限时**带着已有证据降级作答并标注「证据不足」**，绝不返回错误页。

> 面试可讲：为什么不能让 Agent 无限检索（成本 4–12×、延迟 2–8s）、路由为什么是最重要的决策、反思代理的终止校准（第 1 轮应终止 65–75%）。

### I2 · 本机知识图谱层（KG-RAG）—— 最「自然」的融合点
本站已有 4 张结构化数据表（岗位 / 实习 / 投递 / 简历），天生就是图：

- **实体**：公司、岗位、技能标签、状态、时间点、简历项目
- **关系**：`(公司)-[招聘]->(岗位)`、`(岗位)-[要求]->(技能)`、`(投递)-[状态]->(面试)`、`(投递)-[日期]->(时间)`、`(简历)-[具备]->(技能)`
- **检索时**：先做**实体链接**（查询里的「字节 / RAG / 面试」映射到图节点），再 **1~2 跳扩展**取出关联子图，
  与 BM25 候选一起送 **RRF 融合**。
- **多跳问答**：纯 BM25 永远答不好的题，图上一跳就出来——
  「我投过 RAG 相关岗位的公司里，哪些已经面试过？」「哪些公司我既投了岗位又存过复盘？」
- 每条边带 **来源 record_id + 时间戳**（provenance），可回看原文；并统计**三元组覆盖率**。

> 面试可讲：这正是作者 SRTP 项目（KG-RAG 汽车故障诊断，三元组覆盖 ≥95%、准确率 89.7%）的能力平移——
> 从「汽车故障实体-关系」换成「求职实体-关系」，图谱外挂检索的架构一模一样。

### I3 · 混合检索 + RRF 融合 + 三级精排
- **双路召回**：`BM25（已有，权重可调）` + `第二路`。第二路提供**零依赖降级梯度**：
  ① 字符 3-gram / 同义词扩展（纯本地，零下载）→ ② 本机 embedding（transformers.js，`all-MiniLM-L6-v2` q8 约 23MB，WebGPU 优先 / WASM 回落，放 Web Worker 不卡 UI）。
- **RRF 融合**：`score = Σ 1/(k + rank_i)`，`k=60`。**用排名而非分数**，天然解决 BM25 分数与余弦相似度值域不可比的问题；奖励两路一致命中。
- **三级精排**：`字段/实体命中 + 邻近度`（零成本，永远可用）→ `LLM 精排`（有 Key 时，批量复用 `MT_BATCH_MAX=8` 红线）→ 取 Top-4~6。
- **上下文压缩**：命中的长文档按句再做一次轻量 BM25 过滤，只留相关句（对标 LLMLingua 的简化版），直接省 token 与延迟。

### I4 · 记忆三阶段：Storage → Reflection → Experience
论文（ACL 2026 Findings 综述）把 Agent 记忆划成三级，本站可以逐级落地：

- **Storage（已有）**：会话 60 条 + `wb_ai_trace`。
- **Reflection**：本站**唯一的云端写入口就是「面试复盘笔记」**——天然契合。复盘保存时自动抽取「有效策略 / 踩到的坑 / 下次注意」。
- **Experience**：把多次复盘**蒸馏成策略规则**（如「投递前先确认 HC」「一面必问项目细节→先准备 3 分钟版」），
  注入 `agBuildMessages` 的 system 段（人设已有 `sys` 通道）→ Agent 下次**自动遵守**，而不是每次重新检索。
- **治理**：时效衰减 + 冲突检测（新复盘推翻旧结论时标 `superseded` 而不是删）+ **主动记忆感知**（判断这次该不该调记忆，避免旧记忆污染上下文）。

> 面试可讲：「记忆的终点不是海量日志，而是少量好经验」；以及为什么不该把所有记忆塞进同一个向量库。

### I5 · RAG 评测台（把「感觉不错」变成数字）
- **黄金评测集**：50~100 条 `(问题, 标准答案, 应命中文档ID, answerable)`，样本要含口语化 / 缩写 / 多跳 / 无答案（10~20% 无答案样本专门测拒答）。
- **检索指标（确定性、零成本）**：`HitRate@5`、`Recall@5`、`MRR`、`nDCG@5`、`Context Precision`。
- **生成指标（LLM-as-Judge）**：`Faithfulness`（claim 拆解→逐条判是否被支撑）、`Answer Relevancy`（反向生成问题→余弦相似度）、`Citation Correctness`。
- **A/B 调参台**：同一评测集对比 `BM25 k1/b`、`RRF k`、双路权重、Top-K——**从凭感觉调参变成有数据调参**。
- 全部跑在本机，结果导出 Markdown 报告。

### I6 · 可观测轨迹面板
`wb_ai_trace` 已有数据，把它从「调参台内部数组」升级成产品面：每次问答展开一行
`路由决策 → 检索轮次 → 命中数/分数 → 证据评级 → 是否自愈 → 引用校验结果 → token/延迟`。
既是调试利器，也是**演示时最有说服力的一屏**（「Agency without accountability is just unpredictability」）。

## 5. 分期落地（每期独立可用、独立可上线）

| 期 | 内容 | 主要改动 | 验收 |
|---|---|---|---|
| **P1** | I1 闭环 + I6 可观测 | `RAG_JS` 拆出 `ragRoute/ragGrade/ragRewrite/ragVerify`；`ragAsk` 改状态机；轨迹写 `wb_ai_trace` 并新增展示块 | 冒烟：路由三档各 1 例、自愈至少 1 例、拒答 1 例、轨迹字段齐全 |
| **P2** | I3 混合检索 + I5 评测台 | 新增第二路召回与 `rrfFuse()`；精排三级；新增「评测」区块（golden set 本机存储 + 指标计算 + 报告导出） | 同评测集给出 HitRate/MRR/nDCG 基线；A/B 可切换 |
| **P3** | I2 图谱层 | 从 4 张表构建三元组（本机内存图，不入库）；实体链接 + 子图扩展接入 RRF 第三路 | 多跳问答用例通过；三元组覆盖率与 provenance 可见 |
| **P4** | I4 记忆三阶段 | 复盘 → 反思抽取 → 经验规则池 → 注入 `agBuildMessages`；冲突检测与衰减 | 注入前后对同类问题回答可见差异；可一键清空经验 |

> 每期的成本都在可控范围：**检索/融合/评测全是本机确定性计算，零 token**；只有「精排 / 生成 / 判定」在有 Key 时才走模型，
> 且复用既有限额（`MT_BATCH_MAX=8`）与 Mock 兜底，冒烟一律 Mock。

## 6. 不变的红线

零后端 · 单文件 HTML · 数据不出本机 · 离线可用 · Mock 确定性（冒烟预置 `wb_ai_free='0'`）·
构建链五步幂等 · CI 全门禁（含公开版隐私门禁）· 公开版绝不含个人数据 · `syncSeed` 去重键与 `qz_*`/`qc_*` 命名空间不变。
