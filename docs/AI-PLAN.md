# 求职台 AI 能力规划（v2 · 通道已定：用户自带 Key）

> **状态：M0–M6 已全部实现并上线（v27）。** 实际落地与本文档的差异：批量通道最终改为**页面内手动触发**（不做定时自动化）——因为 BYOK 下页面关闭就不该继续烧 token，「常驻后台」的收益与成本不成正比。用户实际使用说明见 **[`docs/AI-FEATURES.md`](docs/AI-FEATURES.md)**。
>
> 已完成清单：M0 AI 设置面板 + LLM 封装 → M1 简历档案（多份 + 意向备注 + AI 解析）+ 投递画像 → M2 简历↔JD 匹配打分 + 按匹配度排序 → M3 面试复盘助手 → M4 批量打分（限额可中断）→ M5 今日 AI 推荐（本地排序 + 按需点评）→ M6 收件箱邮件 AI 解析（页面按钮 + `mail_bridge.py --llm`）→ 附加：抓 JD 书签（零安装）。
>
> 原则：每一步做完都独立可用；不动现有 4 表结构核心字段，只加不改；简历隐私数据只存自己空间。
> **已定**：LLM 通道 = 用户在页面填自己的 API key，存本机 localStorage，页面直连 LLM 接口；开发与冒烟一律走 Mock 模式，不耗任何真实额度。

## 一、总体架构：BYOK 直连 + 自动化批量

| 通道 | 承载功能 | 特点 |
|---|---|---|
| **交互通道**（页面内点按钮即时出结果） | 简历定制、单岗位打分、面试复盘 | 页面 → 用户自己的 API key（localStorage）→ OpenAI 兼容接口直连 |
| **批量通道**（定时自动化，结果写回资料库表） | 邮件智能解析、全量匹配打分、每日岗位推荐 | 每天自动跑，页面只负责展示，零等待 |

- 数据新增：一张新表「简历档案」（结构化简历 + 原文件），岗位表加「匹配度」「AI推荐理由」两个字段，投递跟踪的「复盘笔记」字段复用
- 兜底策略：所有 LLM 调用失败都回落到现有规则逻辑（邮件解析回落 mail_bridge 规则版，打分显示"待评分"），页面永不白屏

## ① AI 设置面板（M0，最先做）
- 个人中心加「AI 设置」卡片：填 API Key（密码框）+ 服务商下拉（DeepSeek / Kimi / 通义 / OpenAI 兼容自定义）+ 模型名，全部存 localStorage（key 前缀 `wb_ai_`）
- 「测试连接」按钮：发一条 1 token 的最小请求验证 key 有效性
- key 只存本机、不上传资料库；界面注明「请勿在公用电脑保存 key」
- **Mock 开关**：未填 key 时自动进入 Mock 模式（返回固定示例结果并标注"演示数据"），开发/冒烟/无 key 用户都能走通全流程
- 直连采用 OpenAI 兼容 `/chat/completions` 格式（DeepSeek/Kimi/通义均兼容）；个别服务商若浏览器 CORS 拦截，设置面板里给出该服务商「不支持浏览器直连」的明确提示

## 二、五个功能拆解

### 1. 简历上传 + AI 定制（P0 地基，其他功能都依赖它）
- 个人中心加「简历档案」卡片：上传 PDF/docx → LLM 抽取结构化档案（技能/项目/实习/教育/亮点）
- 原文件存资料库网盘，结构化结果存「简历档案」表，可手动修正
- **定制**：在任意岗位卡片点「按此岗位定制」→ 生成四块内容：
  ① 匹配亮点（该 JD 最该强调的 3-5 条经历）
  ② 建议改写（把现有经历措辞对齐 JD 关键词，附原文对照）
  ③ 缺口与补强建议
  ④ 一键复制文本

### 2. 简历-JD 匹配度打分
- **单个（交互）**：岗位卡片「测匹配」按钮 → 0-100 分 + 技能/经验/硬性条件三维拆分 + 一句话理由
- **批量（自动化）**：每天早上对全部「待投递」岗位跑一遍，分数写入岗位表「匹配度」字段
- 页面：卡片分数徽章（≥80 绿 / 60-80 橙 / <60 灰）、新增「按匹配度排序」、个人中心显示 Top5 匹配岗位

### 3. 面试复盘助手
- 投递跟踪卡片「记复盘」：口述/粘贴面经 → 生成 STAR 结构复盘 + 暴露的薄弱点 + 下一轮针对性准备清单 → 写入「复盘笔记」
- **面试冲刺卡**：面试前点一下，汇总该公司的历史复盘 + 面试时间地点（来自收件箱）→ 生成当日准备清单
- 时间线：个人中心按公司聚合展示复盘历史

### 4. 岗位推荐（每日）
- 自动化每天结合：简历档案 + 匹配度 + 已投记录（去重）+ 截止时间临近度
- 输出 5-10 条「今日 AI 推荐」，带一句推荐理由，在今日提醒列表顶部单独分组
- 已投/已终止的岗位自动排除

### 5. 邮件解析智能化（升级现有收件箱）
- 现状：mail_bridge.py 纯规则（关键词+置信度），准确但死板
- 升级：自动化拉新邮件 → LLM 结构化解析：公司/岗位/事项类型/具体时间/地点或会议链接/需要你做什么/原文链接，写收件箱表
- 保留现有人工确认流：置信度不足仍进「待确认」，确认后才写投递跟踪

## 五、上线隐私架构（多用户个人使用，互不联通）

- **访客天然隔离**：4 张数据表在作者自己的资料库空间里，其他用户打开页面没有表权限 → 页面自动进离线模式 → 他们的个人数据（投递跟踪/简历档案/AI 结果）只存各自浏览器，物理上碰不到作者的表
- **双模式设计**：已授权账号（作者）= 云同步全功能；未授权访客 = 本地模式 + BYOK AI，功能完整、数据自持
- **上线前加固清单**：
  1. 页面加 CSP meta（限制脚本/连接来源为空 + LLM 服务商域名），XSS 注入面压到最低
  2. 保持零第三方 JS 依赖（已满足，是 XSS 防线的一半）
  3. AI 设置加「记住 key」开关：默认记住（localStorage）/ 关闭则 sessionStorage（关浏览器即失效）
  4. 简历档案等隐私数据仅存本机 + 「一键导出 / 一键清除」按钮
  5. 设置面板固定展示「数据与隐私」声明（发给谁、不发给谁）
- **上线前必测**：无痕窗口打开线上链接，确认①读不到作者表格②AI 功能在本地模式可用③个人数据不外泄
- **未来若要给用户跨设备同步**：才需要账号体系（云服务 end-user auth），现阶段明确不做
